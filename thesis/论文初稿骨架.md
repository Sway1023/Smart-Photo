## 1 绪论

### 1.1 研究背景

写作要点：

- 当前数字照片和视频数量快速增长，个人与家庭用户对存储、整理、浏览和共享提出更高要求。
- 公有云相册虽然使用方便，但在数据自主可控、长期成本和私有化部署方面存在局限。
- 网盘类产品更偏向文件管理逻辑，缺少面向照片浏览的时间线、相册、地点、标签等组织能力。
- 因此，有必要设计一个面向私有化部署场景的共享相册平台，以满足照片集中管理和便捷共享的需求。

可直接展开的写法：

> 随着移动终端拍摄能力的提升，个人与家庭用户积累的照片和视频资源呈现出数量大、类型多、分布散的特点。传统以文件夹为核心的管理方式难以满足用户对时间线浏览、相册归类、共享协作和快速检索的需求。与此同时，主流公有云服务虽然在使用便捷性方面具有一定优势，但在数据自主可控、长期存储成本以及私有化部署方面仍存在明显限制。因此，设计并实现一个基于 Web 技术栈的私有化共享相册平台，具有明确的现实意义和应用价值。

### 1.2 国内外研究概况

建议按三类组织：

- 公有云相册平台
- 私有化存储与相册系统
- 在线相册管理系统研究

写作要点：

- 国内外研究都强调照片资源的集中管理与便捷访问。
- 当前方案往往在数据控制权、功能完整度和部署成本之间难以兼顾。
- 本课题更关注轻量化私有部署、核心相册业务闭环和多场景共享能力。

### 1.3 本文研究工作

建议写法：

- 完成了一个基于 Node.js 与 Svelte 的私有化共享相册平台方案设计。
- 系统围绕用户认证、照片库管理、相册管理、共享协作、检索与地图浏览等核心业务展开。
- 采用前后端分离的 B/S 架构，并结合 PostgreSQL 与 Redis 支撑系统运行。
- 对系统进行了需求分析、功能模块设计、数据库设计、系统实现说明与测试分析。

## 2 系统的需求分析

### 2.1 系统可行性分析

#### 2.1.1 技术可行性分析

写作要点：

- 前端采用 Svelte，适合构建页面交互清晰的单页应用。
- 后端采用 Node.js + NestJS，适合组织模块化接口服务。
- PostgreSQL 负责结构化数据存储，Redis 用于系统缓存和任务支撑。
- 项目采用 B/S 架构，适合多终端浏览器访问。

#### 2.1.2 经济可行性分析

写作要点：

- 采用开源软件栈，降低软件授权成本。
- 部署方式灵活，可运行于个人服务器或普通主机环境。
- 相比重型商业存储系统，整体投入更可控。

#### 2.1.3 运行可行性分析

写作要点：

- 用户使用浏览器即可访问系统，使用门槛低。
- 系统操作流程围绕照片浏览与共享展开，符合目标用户日常习惯。
- 管理员和普通用户的权限边界清晰，便于运行维护。

### 2.2 系统功能性需求

本节应先用文字说明角色，再引用系统用例图。

角色建议固定为：

- 管理员
- 注册用户
- 共享访问者

#### 2.2.1 管理员功能需求

- 用户维护
- 查看系统内用户数据
- 维护用户状态与权限范围

#### 2.2.2 注册用户功能需求

- 登录系统
- 浏览照片时间线
- 上传与管理照片资源
- 创建和维护相册
- 生成共享链接
- 与其他用户进行共享协作
- 使用检索、标签、地图与地点浏览功能
- 维护个人设置与会话信息

#### 2.2.3 共享访问者功能需求

- 通过共享链接访问指定内容
- 在授权范围内查看共享资源
- 在设置密码时完成验证后再访问内容

### 2.3 系统非功能性需求

建议按以下四类写：

- 性能需求
  页面响应合理，资源浏览流畅，常见查询能在较短时间内返回。
- 安全性需求
  用户登录、会话校验、权限控制、共享访问保护。
- 可维护性需求
  前后端模块化清晰，接口边界明确，便于后期扩展。
- 易用性需求
  页面分区符合用户心智，侧边栏导航清晰，常用功能可快速访问。
